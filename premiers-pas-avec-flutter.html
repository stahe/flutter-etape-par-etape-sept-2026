    3.1. Exemple 01 : la structure d'une application Flutter

    3.1.1. Le projet

    Un projet [Flutter] se crée avec la commande [flutter create] :

    1
    flutter create --org fr.stahe --platforms=android,web,windows mon_application
    • [--org fr.stahe] : le préfixe de l'identifiant de l'application, à l'envers comme un nom de domaine. L'application [Android] s'appellera [fr.stahe.mon_application] ; deux applications installées sur un même téléphone doivent avoir des identifiants différents ;
    • [--platforms=...] : les plateformes visées. Pour chacune, [flutter create] fabrique un dossier ([android/], [web/], [windows/], et aussi [ios/], [macos/], [linux/] si on les demande) : un petit projet propre à la plateforme, qui se contente de démarrer le moteur de [Flutter] et d'y charger l'application. On n'y touche que rarement (le nom de l'application, son icône, ses permissions) ;
    • [mon_application] : le nom du projet, qui est aussi celui du paquet [Dart] : des minuscules, des chiffres et des soulignés.

    La commande fabrique une application complète, prête à être lancée (un compteur). Le projet des exemples a été créé de la même façon, puis son dossier [lib/] a été rempli à la main, pour réunir vingt-cinq applications dans un même projet : elles partagent ainsi les mêmes paquets, téléchargés une seule fois.

    • lignes 24-45 : les paquets dont l'application a besoin. Certains viennent du SDK de [Flutter] lui-même ([sdk: flutter]) : [flutter] (le framework), [flutter_localizations] (les textes de [Flutter] traduits dans chaque langue), [flutter_web_plugins] (un réglage propre au web). [intl: any] : n'importe quelle version (c'est [flutter_localizations] qui impose la sienne) ;
    • lignes 47-52 : les paquets qui ne servent qu'au développement, et ne font pas partie de l'application livrée : [flutter_test] (les tests) et [flutter_lints] (les règles de style de l'analyseur) ;
    • lignes 54-67 : la configuration propre à [Flutter] :
      • [uses-material-design: true] : l'application utilise la police d'icônes de [Material Design] ([Icons.add], [Icons.delete]...) ;
      • [assets] : les fichiers livrés avec l'application (images, dictionnaires...), qu'on lira par leur chemin. Déclarer un dossier ([assets/]) livre tous les fichiers qu'il contient directement ;
      • [fonts] : une police de caractères livrée avec l'application, [Roboto Mono], une police à chasse fixe, pour afficher du JSON. La police normale de [Material Design], [Roboto], est celle du système [Android] : inutile de la livrer.

    Les versions des paquets suivent la même convention que [npm] : [^16.2.0] accepte toute version 16.x.y à partir de 16.2.0. La commande [flutter pub get] télécharge les paquets et écrit les versions exactes retenues dans le fichier [pubspec.lock]. Elle est lancée automatiquement par [flutter run] quand [pubspec.yaml] a changé ; [VS Code] la lance aussi dès qu'on enregistre ce fichier. Pour ajouter un paquet, plutôt que de modifier le fichier à la main, on peut taper [flutter pub add go_router] : la commande ajoute la ligne, avec la dernière version du paquet.

    // =========================================================================
// lib/ex01_premiere_application/main.dart - une première application
// -------------------------------------------------------------------------
// Tout, dans une application Flutter, est un WIDGET : un objet qui décrit
// un morceau de l'écran (un texte, un bouton, une marge, une colonne...).
// Les widgets s'emboîtent les uns dans les autres et forment un ARBRE.
// Un widget a une méthode build(), qui RENVOIE les widgets qui le
// composent. Flutter appelle build() pour fabriquer l'écran ; il la
// RAPPELLE chaque fois que l'état du widget change (setState), et met à
// jour l'écran avec le nouveau résultat.
// =========================================================================

import 'package:flutter/material.dart';

// des données "ordinaires", hors des widgets : elles ne changent jamais
const titre = 'Bienvenue dans Flutter';
const langages = ['Dart', 'Flutter', 'Material Design'];

// "12:05:09" : l'heure courante, sur deux chiffres
String heureCourante() {
  final d = DateTime.now();
  String deuxChiffres(int n) => n.toString().padLeft(2, '0');
  return '${deuxChiffres(d.hour)}:${deuxChiffres(d.minute)}:${deuxChiffres(d.second)}';
}

// le point d'entrée de tout programme Dart
void main() {
  // runApp : Flutter prend possession de l'écran et y affiche le widget RACINE
  runApp(const Application());
}

// le widget racine : il configure l'application (titre, thème, premier écran).
// StatelessWidget : un widget SANS état, entièrement décrit par ses paramètres
class Application extends StatelessWidget {
  const Application({super.key});

  @override
  Widget build(BuildContext context) {
    // MaterialApp : une application aux couleurs et au comportement de
    // Material Design, le langage visuel de Google
    return MaterialApp(
      title: 'Exemple 01',
      // pas de bandeau "DEBUG" dans le coin de l'écran
      debugShowCheckedModeBanner: false,
      // les couleurs de toute l'application, déduites d'une couleur de base
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const PageAccueil(),
    );
  }
}

// un widget AVEC état : il est en deux parties, le widget lui-même (qui ne
// change jamais) et un objet State (qui contient les données qui changent)
class PageAccueil extends StatefulWidget {
  const PageAccueil({super.key});

  @override
  State<PageAccueil> createState() => _PageAccueilState();
}

// le "_" : cette classe est PRIVÉE, invisible hors de ce fichier
class _PageAccueilState extends State<PageAccueil> {
  // l'ÉTAT : de simples champs de l'objet State
  int _compteur = 0;
  String _heure = heureCourante();

  // la fonction appelée par le bouton
  void _incrementer() {
    // setState : on modifie l'état DANS la fonction passée à setState ;
    // Flutter rappelle alors build() pour mettre l'écran à jour. On ne
    // modifie jamais l'écran soi-même
    setState(() {
      _compteur++;
      _heure = heureCourante();
    });
  }

  @override
  Widget build(BuildContext context) {
    // Scaffold : la structure d'un écran Material (barre du haut, corps...)
    return Scaffold(
      appBar: AppBar(title: const Text('Exemple 01 - une première application')),
      // Padding : une marge autour de son enfant (child)
      body: Padding(
        padding: const EdgeInsets.all(16),
        // Column : des enfants (children) placés les uns sous les autres
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Text(titre, style: Theme.of(context).textTheme.headlineSmall),
            const SizedBox(height: 12),
            const Text(
              'Cet écran est fabriqué par Flutter, à partir de la fonction main '
              'et des widgets Application et PageAccueil.',
            ),
            const SizedBox(height: 8),
            // ${expression} insère la valeur d'une expression dans une chaîne
            Text('On y écrit du ${langages.join(', ')} (${langages.length} langages).'),
            const SizedBox(height: 16),
            // onPressed : la fonction à appeler quand on appuie (cf. exemple 04)
            FilledButton(onPressed: _incrementer, child: const Text('Cliquez-moi')),
            const SizedBox(height: 16),
            Text(
              'Vous avez cliqué $_compteur fois (dernier clic : $_heure).',
              style: const TextStyle(fontWeight: FontWeight.bold, color: Color(0xFF087EA4)),
            ),
          ],
        ),
      ),
    );
  }
}

    Commençons par la fin : le programme.

    • ligne 13 : la bibliothèque [Material] de [Flutter] : tous les widgets de [Material Design], le langage visuel de [Google] (boutons, champs de saisie, barres, fenêtres...). Elle importe elle-même le reste de [Flutter] ;
    • lignes 16-17 : deux données ordinaires, déclarées hors des widgets : elles ne changent jamais. [const] : une constante connue dès la compilation ;
    • lignes 20-23 : une fonction ordinaire, qui renvoie l'heure courante sous la forme « 12:05:09 ». Elle contient elle-même une petite fonction, [deuxChiffres], écrite en une ligne avec [=>] ;
    • lignes 27-29 : la fonction [main], appelée au lancement. [runApp] démarre [Flutter] : il prend possession de l'écran et y affiche le widget qu'on lui donne, la racine de l'application.

    Le widget racine, [Application] :

    • ligne 34 : un widget est une classe. Celle-ci hérite de [StatelessWidget], un widget sans état : ce qu'il affiche ne dépend que de ses paramètres, et ne change jamais de lui-même ;
    • ligne 29 : son constructeur. [{super.key}] : un paramètre nommé, facultatif, transmis à la classe mère. Tout widget en a un : la « clé » qui l'identifie (cf. exemple 04). Le constructeur est [const] : [Application()] peut être une constante, que [Flutter] n'a jamais besoin de reconstruire ;
    • lignes 38-47 : la méthode [build], le cœur d'un widget. Elle renvoie les widgets qui le composent. [@override] : elle redéfinit la méthode [build] de la classe mère. Le paramètre [context] est la position du widget dans l'arbre des widgets : il sert à retrouver ce que ses ancêtres fournissent (le thème, par exemple, ligne 90) ;
    • lignes 41-47 : [MaterialApp] est le widget qui fait d'un arbre de widgets une application [Material] : un titre ([title], le nom de l'application dans la liste des applications récentes du téléphone, ou de l'onglet du navigateur), un thème ([theme]), un premier écran ([home]). [debugShowCheckedModeBanner: false] retire le bandeau « DEBUG » qu'une application en développement affiche dans un coin. [ThemeData(colorSchemeSeed: Colors.indigo)] : toutes les couleurs de l'application (boutons, barres, champs...) sont déduites d'une seule couleur de base, selon les règles de [Material Design] 3.

    Le premier écran, [PageAccueil], a des données qui changent : c'est un widget avec état.

    • lignes 54-58 : un [StatefulWidget] est en deux parties. Le widget lui-même, comme tout widget, ne change jamais (ses champs seraient [final]) ; sa seule tâche est de fabriquer, par [createState], un objet [State] qui, lui, contient les données qui changent. [Flutter] crée cet objet une seule fois et le garde tant que le widget reste à la même place dans l'arbre ;
    • ligne 62 : l'objet [State]. Son nom commence par un souligné : en [Dart], tout ce qui commence par [_] est privé, invisible hors du fichier ;
    • lignes 64-65 : l'état : de simples champs de l'objet [State] ;
    • lignes 68-75 : la méthode appelée par le bouton. Elle ne touche pas à l'écran : elle change l'état, dans la fonction passée à [setState]. [setState] exécute cette fonction, puis prévient [Flutter] que l'état a changé : [Flutter] rappellera [build], comparera le nouvel arbre de widgets à l'ancien, et redessinera ce qui a changé ;
    • lignes 79-105 : le [build] de l'écran :
      • [Scaffold] (« échafaudage ») est la structure d'un écran [Material] : une barre du haut ([appBar]), un corps ([body]), et, si on les demande, une barre du bas, un bouton flottant, un menu latéral ;
      • [AppBar] : la barre du haut ; son titre est un widget ([Text]), comme presque tout en [Flutter] ;
      • [Padding] : une marge autour de son unique enfant, [child]. [EdgeInsets.all(16)] : 16 points de chaque côté (un « point » logique, indépendant de la densité de l'écran : environ 2,6 pixels sur le téléphone des copies d'écran) ;
      • [Column] : ses enfants, [children], placés les uns sous les autres. [crossAxisAlignment: CrossAxisAlignment.start] : alignés à gauche (l'axe « transversal » d'une colonne est l'horizontale) ;
      • [Text] : un texte. Son style peut venir du thème : [Theme.of(context).textTheme.headlineSmall] est le style des « petits grands titres » ;
      • [SizedBox] : une boîte vide, d'une hauteur donnée : un espace entre deux widgets ;
      • ligne 98 : [${expression}] insère la valeur d'une expression dans une chaîne ; [$nom] suffit pour une simple variable (ligne 104) ;
      • ligne 101 : un bouton. [onPressed] reçoit la fonction à appeler quand on appuie. On donne la fonction elle-même, sans parenthèses : [onPressed: _incrementer()] l'appellerait tout de suite, pendant la construction de l'écran ;
      • lignes 104-105 : un texte qui dépend de l'état. Quand l'état change, [build] est rappelée, et ce texte change.

    Deux remarques de [Dart] :

    • les arguments des widgets sont presque tous des paramètres nommés ([title: ...], [child: ...]) : l'arbre des widgets se lit comme une description, et l'ordre des arguments n'importe pas. Un paramètre nommé est facultatif, sauf s'il est déclaré [required] ;
    • le mot-clé [const] devant un widget ([const SizedBox(height: 12)]) le fabrique une fois pour toutes, à la compilation. [Flutter] sait alors qu'il ne change jamais, et ne perd pas de temps à le comparer. L'analyseur signale les [const] qu'on a oubliés ; [VS Code] sait les ajouter tout seul.

// lib/ex02_etat/main.dart - l'état et les valeurs calculées
// -------------------------------------------------------------------------
// Un petit calculateur de prix TTC :
//   - l'ÉTAT : les champs de l'objet State ; les changer DANS setState()
//     fait rappeler build(), qui fabrique l'écran avec les nouvelles valeurs ;
//   - une valeur CALCULÉE à partir de l'état n'est PAS un état : c'est un
//     "getter" (ou une variable locale de build), recalculé à chaque appel
//     de build(). Il est toujours à jour, sans rien à synchroniser ;
//   - une donnée qui dépend des valeurs SUCCESSIVES de l'état (l'historique
//     des totaux) se met à jour là où l'état change : dans setState ;
//   - le titre de l'application (onglet du navigateur, liste des
//     applications récentes du téléphone) est lui aussi un widget, Title :
//     il suit l'état comme le reste de l'écran.
// =========================================================================

import 'package:flutter/material.dart';
import 'package:intl/intl.dart';

// un formateur de montants en euros, à la française (1 234,50 €), cf. exemple 09
final euros = NumberFormat.currency(locale: 'fr_FR', symbol: '€');

void main() {
  runApp(
    MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const PageCalculateur(),
    ),
  );
}

class PageCalculateur extends StatefulWidget {
  const PageCalculateur({super.key});

  @override
  State<PageCalculateur> createState() => _PageCalculateurState();
}

class _PageCalculateurState extends State<PageCalculateur> {
  // l'état
  String _libelle = 'Stylo';
  double _prixHT = 2.5;
  int _quantite = 1;
  double _tauxTVA = 20; // en %
  // l'historique des 5 derniers changements du total TTC
  final List<String> _historique = [];

  // un contrôleur donne accès au TEXTE d'un champ de saisie : on en a besoin
  // ici pour le remettre à sa valeur de départ (Réinitialiser). L'exemple 05
  // les étudie en détail
  final _champLibelle = TextEditingController(text: 'Stylo');
  final _champPrix = TextEditingController(text: '2.5');

  // des valeurs CALCULÉES : des getters, recalculés à chaque lecture
  double get _totalHT => _quantite * _prixHT;
  double get _montantTVA => _totalHT * _tauxTVA / 100;
  double get _totalTTC => _totalHT + _montantTVA;

  // TOUS les changements de l'état passent par cette méthode : elle note le
  // total TTC avant le changement, applique le changement, et complète
  // l'historique si le total a changé
  void _changer(void Function() changement) {
    final ancienTTC = _totalTTC;
    setState(() {
      changement();
      if (_totalTTC != ancienTTC) {
        _historique.insert(0, '${euros.format(ancienTTC)} -> ${euros.format(_totalTTC)}');
        if (_historique.length > 5) {
          _historique.removeLast();
        }
      }
    });
  }

  // changer d'article remet la quantité à 1 : on le fait là où l'on sait
  // POURQUOI l'état change
  void _changerLibelle(String nouveau) {
    _changer(() {
      _libelle = nouveau;
      _quantite = 1;
    });
  }

  void _reinitialiser() {
    _changer(() {
      _libelle = 'Stylo';
      _prixHT = 2.5;
      _quantite = 1;
      _tauxTVA = 20;
    });
    _champLibelle.text = 'Stylo';
    _champPrix.text = '2.5';
  }

  // l'objet State disparaît (on quitte l'écran) : on libère les contrôleurs
  @override
  void dispose() {
    _champLibelle.dispose();
    _champPrix.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final styleTotal = Theme.of(context).textTheme.titleMedium!.copyWith(fontWeight: FontWeight.bold);

    // Title : le titre de l'application SUIT l'état, comme tout le reste
    return Title(
      title: 'TTC : ${euros.format(_totalTTC)}',
      color: Colors.indigo,
      child: Scaffold(
        appBar: AppBar(title: const Text("Exemple 02 - l'état")),
        // ListView : une colonne qui défile si elle dépasse la hauteur de l'écran
        body: ListView(
          padding: const EdgeInsets.all(16),
          children: [
            Card(
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Column(
                  children: [
                    // onChanged : appelée à chaque frappe, avec le nouveau texte
                    TextField(
                      controller: _champLibelle,
                      decoration: const InputDecoration(labelText: 'Article'),
                      onChanged: _changerLibelle,
                    ),
                    TextField(
                      controller: _champPrix,
                      decoration: const InputDecoration(labelText: 'Prix unitaire HT'),
                      // le clavier numérique du téléphone, avec la virgule
                      keyboardType: const TextInputType.numberWithOptions(decimal: true),
                      // tryParse : null si le texte n'est pas un nombre ; on accepte la virgule
                      onChanged: (texte) => _changer(() => _prixHT = double.tryParse(texte.replaceAll(',', '.')) ?? 0),
                    ),
                    const SizedBox(height: 12),
                    Row(
                      children: [
                        const Expanded(child: Text("Quantité (revient à 1 si l'article change)")),
                        IconButton(
                          icon: const Icon(Icons.remove),
                          // null : le bouton est désactivé
                          onPressed: _quantite > 0 ? () => _changer(() => _quantite--) : null,
                        ),
                        Text('$_quantite', style: styleTotal),
                        IconButton(icon: const Icon(Icons.add), onPressed: () => _changer(() => _quantite++)),
                      ],
                    ),
                    const SizedBox(height: 8),
                    // des boutons dont UN seul est sélectionné : le taux de TVA
                    SegmentedButton<double>(
                      segments: const [
                        ButtonSegment(value: 5.5, label: Text('5,5 %')),
                        ButtonSegment(value: 10, label: Text('10 %')),
                        ButtonSegment(value: 20, label: Text('20 %')),
                      ],
                      selected: {_tauxTVA},
                      onSelectionChanged: (choix) => _changer(() => _tauxTVA = choix.first),
                    ),
                    const SizedBox(height: 12),
                    OutlinedButton(onPressed: _reinitialiser, child: const Text('Réinitialiser')),
                  ],
                ),
              ),
            ),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Column(
                  crossAxisAlignment: CrossAxisAlignment.start,
                  children: [
                    Text('$_quantite x $_libelle', style: Theme.of(context).textTheme.titleLarge),
                    const Divider(),
                    _ligne('Total HT', euros.format(_totalHT)),
                    _ligne('TVA (${_tauxTVA.toString().replaceAll('.', ',')} %)', euros.format(_montantTVA)),
                    _ligne('Total TTC', euros.format(_totalTTC), style: styleTotal),
                  ],
                ),
              ),
            ),
            Card(
              child: Padding(
                padding: const EdgeInsets.all(16),
                child: Column(
                  crossAxisAlignment: CrossAxisAlignment.start,
                  children: [
                    Text('Historique du total TTC', style: Theme.of(context).textTheme.titleSmall),
                    // une ligne de texte par élément de l'historique (cf. exemple 03)
                    for (final ligne in _historique) Text('• $ligne'),
                  ],
                ),
              ),
            ),
          ],
        ),
      ),
    );
  }

  // une ligne "libellé ....... montant" : une méthode qui fabrique des widgets
  Widget _ligne(String libelle, String montant, {TextStyle? style}) {
    return Padding(
      padding: const EdgeInsets.symmetric(vertical: 4),
      child: Row(
        children: [
          Expanded(child: Text(libelle, style: style)),
          Text(montant, style: style),
        ],
      ),
    );
  }

    • lignes 42-45 : quatre données d'état, de simples champs, typés : [String], [double], [int]. En [Dart], [int] et [double] sont deux types de nombres distincts ;

// lib/ex03_widgets/main.dart - écrire un arbre de widgets
// -------------------------------------------------------------------------
// Flutter n'a pas de langage de gabarits (pas de HTML, pas de JSX) : les
// écrans sont écrits en Dart, avec des constructeurs de widgets imbriqués.
// Pour les conditions et les boucles, Dart offre des outils faits pour
// fabriquer des LISTES d'enfants (children: [...]) :
//   - if (condition) widget          : un enfant qui n'EXISTE que si la
//                                      condition est vraie ("collection if") ;
//   - if (c) widgetA else widgetB    : l'un OU l'autre ;
//   - condition ? widgetA : widgetB  : pareil, dans une expression ;
//   - for (final x in liste) widget  : un enfant par élément de la liste
//                                      ("collection for") ;
//   - ...autreListe                  : les éléments d'une autre liste,
//                                      insérés à cet endroit ("spread") ;
//   - switch (valeur) { motif => ... } : une valeur parmi plusieurs.
// Et tout ce qui est avant le return de build() est du code ordinaire.
// =========================================================================

import 'package:flutter/material.dart';
import 'package:flutter_svg/flutter_svg.dart';

// une "énumération" : les seules valeurs possibles d'une spécialité
enum Specialite { generaliste, pediatre, cardiologue }

// une classe de données : ses champs sont final, un objet Medecin ne change
// jamais. Le constructeur "const" permet d'en faire des constantes
class Medecin {
  final int id;
  final String titre;
  final String prenom;
  final String nom;
  final Specialite specialite;
  final bool disponible;

  const Medecin(this.id, this.titre, this.prenom, this.nom, this.specialite, this.disponible);
}

const medecins = [
  Medecin(1, 'Mme', 'Marie', 'PELISSIER', Specialite.generaliste, true),
  Medecin(2, 'Mr', 'Paul', 'TATOU', Specialite.pediatre, false),
  Medecin(3, 'Melle', 'Sophie', 'DUPONT', Specialite.cardiologue, true),
];

// "une valeur parmi plusieurs, selon une valeur" : une EXPRESSION switch.
// Le compilateur vérifie que tous les cas de l'énumération sont traités
String libelle(Specialite s) => switch (s) {
  Specialite.generaliste => 'généraliste',
  Specialite.pediatre => 'pédiatre',
  Specialite.cardiologue => 'cardiologue',
};

Icon icone(Specialite s) => switch (s) {
  Specialite.pediatre => const Icon(Icons.child_care, color: Colors.orange),
  Specialite.cardiologue => const Icon(Icons.favorite, color: Colors.red),
  _ => const Icon(Icons.medical_services, color: Colors.teal), // "_" : tous les autres cas
};

void main() {
  runApp(
    MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const PageMedecins(),
    ),
  );
}

  const PageMedecins({super.key});

  @override
  State<PageMedecins> createState() => _PageMedecinsState();
}

class _PageMedecinsState extends State<PageMedecins> {
  String _filtre = ''; // le texte recherché
  bool _seulementDisponibles = false;
  bool _afficherAide = true;

  @override
  Widget build(BuildContext context) {
    // la liste affichée : une variable ordinaire, recalculée à chaque build()
    final texte = _filtre.trim().toLowerCase();
    final affiches = medecins
        .where(
          (m) =>
              (!_seulementDisponibles || m.disponible) &&
              '${m.prenom} ${m.nom} ${libelle(m.specialite)}'.toLowerCase().contains(texte),
        )
        .toList();

    // "l'un des trois blocs" : on le calcule AVANT le return, avec des if
    final Widget contenu;
    if (medecins.isEmpty) {
      contenu = const Text('Aucun médecin.');
    } else if (affiches.isEmpty) {
      contenu = Text('Aucun médecin ne correspond à « $_filtre ».', style: const TextStyle(color: Colors.deepOrange));
    } else {
      contenu = Column(
        children: [
          // un enfant par médecin : "collection for", avec son rang (indexed)
          for (final (i, m) in affiches.indexed)
            // Opacity : les médecins indisponibles sont grisés
            Opacity(
              opacity: m.disponible ? 1 : 0.5,
              // ListTile : une ligne de liste Material (icône, titre, sous-titre, fin)
              child: ListTile(
                leading: CircleAvatar(child: Text('${i + 1}')),
                title: Text('${m.titre} ${m.prenom} ${m.nom}'),
                // Wrap : comme une Row, mais qui passe à la ligne si la place manque
                subtitle: Wrap(
                  spacing: 6,
                  crossAxisAlignment: WrapCrossAlignment.center,
                  children: [icone(m.specialite), Text(libelle(m.specialite))],
                ),
                trailing: Chip(
                  label: Text(m.disponible ? 'disponible' : 'indisponible'),
                  // une couleur choisie par une expression conditionnelle
                  backgroundColor: m.disponible ? Colors.green.shade100 : Colors.grey.shade300,
                ),
              ),
            ),
        ],
      );
    }

    return Scaffold(
      appBar: AppBar(
        // une image SVG livrée avec l'application (dossier assets/, cf. pubspec.yaml)
        leading: Padding(padding: const EdgeInsets.all(12), child: SvgPicture.asset('assets/medecin.svg')),
        title: const Text('Exemple 03 - les widgets'),
      ),
      body: ListView(

// lib/ex04_evenements/main.dart - réagir aux actions de l'utilisateur
// -------------------------------------------------------------------------
// Un widget interactif reçoit en paramètres les FONCTIONS à appeler quand
// il se passe quelque chose ("callbacks") :
//   - onPressed: f                  : f est appelée à l'appui (boutons) ;
//   - onPressed: () => supprimer(t) : une fonction anonyme, pour passer ses
//                                     propres arguments ;
//   - onChanged, onSubmitted...     : la fonction reçoit une donnée (le
//                                     texte, la case cochée...) ;
//   - GestureDetector               : ajoute des gestes (appui, appui long,
//                                     double appui, glissement...) à
//                                     N'IMPORTE QUEL widget ;
//   - Dismissible                   : faire glisser une ligne pour la retirer,
//                                     le geste typique d'un mobile.
// Pour agir sur un champ de saisie depuis le code (lire ou effacer son
// texte, lui donner le focus), on lui associe un CONTRÔLEUR et un FocusNode.
// =========================================================================

import 'package:flutter/material.dart';
import 'package:flutter/services.dart';

class Tache {
  final int id;
  final String libelle;
  bool faite;

  Tache(this.id, this.libelle, {this.faite = false});
}

void main() {
  runApp(
    MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: const PageTaches(),
    ),
  );
}

class PageTaches extends StatefulWidget {
  const PageTaches({super.key});

  @override
  State<PageTaches> createState() => _PageTachesState();
}

class _PageTachesState extends State<PageTaches> {
  final List<Tache> _taches = [
    Tache(1, 'Installer Flutter', faite: true),
    Tache(2, 'Lire le chapitre sur les événements'),
  ];
  final List<String> _journal = [];
  // le contrôleur du champ : son texte (lecture, écriture) ;
  // le FocusNode : son focus (le curseur et le clavier du téléphone)
  final _champ = TextEditingController();
  final _focus = FocusNode();
  // un champ de l'objet State qui n'est PAS affiché : le modifier ne
  // demande aucun setState
  int _prochainId = 3;

  @override
  void dispose() {
    _champ.dispose();
    _focus.dispose();
    super.dispose();
  }

  void _tracer(String message) {
    final t = TimeOfDay.now();
    _journal.insert(0, '${t.format(context)} $message');
  }

  // appelée par le bouton ET par la touche Entrée du clavier (onSubmitted)
  void _ajouter() {
    final libelle = _champ.text.trim();
    if (libelle.isEmpty) {
      return;
    }
    setState(() {
      _taches.add(Tache(_prochainId++, libelle));
      _tracer('ajout de « $libelle »');
    });
    _champ.clear();
    // le focus revient au champ : on peut taper la tâche suivante
    _focus.requestFocus();
  }

  void _basculer(Tache tache, bool faite) {
    setState(() {
      tache.faite = faite;
      _tracer('« ${tache.libelle} » : ${faite ? 'faite' : 'à faire'}');
    });
  }

  void _supprimer(Tache tache, String comment) {
    setState(() {
      _taches.remove(tache);
      _tracer('suppression de « ${tache.libelle} » ($comment)');
    });
  }

  // les détails d'un appui : sa position, relative au widget touché
  void _position(TapDownDetails details) {
    final p = details.localPosition;
    setState(() => _tracer('appui en (${p.dx.round()}, ${p.dy.round()})'));
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Exemple 04 - les événements')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Row(
            children: [
              Expanded(
                // CallbackShortcuts : des raccourcis clavier (un clavier
                // physique : ordinateur, émulateur, tablette) ; Échap vide le champ
                child: CallbackShortcuts(
                  bindings: {const SingleActivator(LogicalKeyboardKey.escape): _champ.clear},
                  child: TextField(
                    controller: _champ,
                    focusNode: _focus,
                    decoration: const InputDecoration(hintText: 'nouvelle tâche (Échap pour vider)'),
                    // la touche "Entrée" du clavier du téléphone
                    textInputAction: TextInputAction.done,
                    onSubmitted: (_) => _ajouter(),
                  ),
                ),
              ),
              const SizedBox(width: 8),
              FilledButton(onPressed: _ajouter, child: const Text('Ajouter')),
            ],
          ),
          const SizedBox(height: 12),
          for (final t in _taches)
            // Dismissible : faire glisser la ligne vers la gauche la retire.
            // key : l'IDENTITÉ de la ligne, pour que Flutter sache laquelle
            // a disparu (cf. l'explication du cours)
            Dismissible(
              key: ValueKey(t.id),
              direction: DismissDirection.endToStart,
              background: Container(
                color: Colors.red.shade100,
                alignment: Alignment.centerRight,
                padding: const EdgeInsets.only(right: 16),
                child: const Icon(Icons.delete),
              ),
              onDismissed: (_) => _supprimer(t, 'glissement'),
              child: CheckboxListTile(
                // la case est À GAUCHE, comme sur une liste de tâches
                controlAffinity: ListTileControlAffinity.leading,
                value: t.faite,
                // la case transmet sa nouvelle valeur (bool?, d'où le "!")
                onChanged: (coche) => _basculer(t, coche!),
                title: Text(
                  t.libelle,
                  style: t.faite ? const TextStyle(decoration: TextDecoration.lineThrough, color: Colors.grey) : null,
                ),
                // une fonction anonyme : la tâche de CETTE ligne en argument
                secondary: IconButton(
                  icon: const Icon(Icons.delete_outline, color: Colors.red),
                  onPressed: () => _supprimer(t, 'bouton'),
                ),
              ),
            ),
          const SizedBox(height: 12),
          // GestureDetector : un widget quelconque devient sensible aux gestes
          GestureDetector(
            onTapDown: _position,
            onDoubleTap: () => setState(() => _tracer('double appui')),
            onLongPress: () => setState(() => _tracer('appui long')),
            child: Container(
              height: 80,
              alignment: Alignment.center,
              decoration: BoxDecoration(color: const Color(0xFFE7F5FF), borderRadius: BorderRadius.circular(8)),
              child: const Text('Touchez cette zone (appui, double appui, appui long)'),
            ),
          ),
          const SizedBox(height: 16),
          Text('Journal', style: Theme.of(context).textTheme.titleSmall),
          for (final ligne in _journal) Text(ligne, style: const TextStyle(fontSize: 12)),
        ],
      ),
    );
  }
}

// seule source de vérité. Modifier l'état (par le code) modifie le champ.
// Ce que transmet onChanged dépend du champ :
//   - TextField (avec un contrôleur)   -> le texte (String) ;
//   - Checkbox, Switch                 -> bool? / bool ;
//   - Radio (dans un RadioGroup)       -> la valeur du bouton choisi ;
//   - DropdownButton                   -> la valeur de l'élément choisi ;
//   - FilterChip                       -> bool : la puce est-elle choisie ?
//   - Slider                           -> double ;
//   - showDatePicker (une fenêtre)     -> un Future<DateTime?>.
// Le TextField est un cas à part : il garde son texte dans un
// TextEditingController, qu'on crée, qu'on lit (controller.text), qu'on
// modifie... et qu'on libère (dispose).
// Même formulaire que l'exemple 05 du cours React ; tout se passe sur le
// téléphone, sans serveur.
// =========================================================================

    • lignes 39-41 : les textes de [Flutter] lui-même (les jours et les mois du calendrier, les boutons « OK » et « ANNULER » de ses fenêtres) sont en anglais par défaut. Un contrôleur prévient de chaque changement de son texte ceux qui l'écoutent ([addListener]) : on redessine l'écran, pour que le modèle affiché en bas suive la saisie.     • ligne 87 : la date au format de l'API [RdvMedecins], « 2026-10-05 ». [_naissance?.toIso8601String()] : l'opérateur [?.] n'appelle la méthode que si [_naissance] n'est pas [null] (sinon, le résultat est [null]) ;

// lib/ex06_reducteur/main.dart - un formulaire, un objet, un réducteur
// -------------------------------------------------------------------------
// L'exemple 05 avait un champ d'état par champ du formulaire. Pour un vrai
// formulaire, on préfère UN objet qui contient toutes les valeurs, le
// MODÈLE (ici un objet Profil, non modifiable), et l'on décrit ses
// changements dans une seule fonction, le RÉDUCTEUR :
//
//     reducteur(etatActuel, action) -> nouvelEtat
//
// Le widget ne modifie plus l'état : il DÉCRIT ce qui s'est passé, par un
// objet ActionProfil (Modifier(Champ.nom, 'Dupont'), Quitter(Champ.nom)...), et
// le réducteur en déduit le nouvel état. Toute la logique est en un
// endroit, dans une fonction PURE (même entrée, même sortie, aucun effet
// de bord), facile à tester.
// Dart s'y prête bien : une classe "sealed" énumère toutes les actions
// possibles, et un switch sur une action est vérifié par le compilateur
// (un cas oublié est une erreur).
//
// L'état garde aussi, pour chaque champ, s'il a été "touché" (quitté au
// moins une fois) ; on en déduit s'il est "modifié" (sa valeur diffère de
// la valeur de départ) et s'il est désactivé.
// =========================================================================

import 'dart:convert';

import 'package:flutter/material.dart';

// le nom de chaque champ du formulaire
enum Champ { titre, prenom, nom, age, newsletter, email, pays, naissance, presentation }

// les données du formulaire : un objet NON MODIFIABLE (tous ses champs sont
// final). Pour le "modifier", on en fabrique un nouveau (copyWith)
class Profil {
  final String titre;
  final String prenom;
  final String nom;
  final int age;
  final bool newsletter;
  final String email;
  final String pays;
  final String naissance;
  final String presentation;

  const Profil({
    required this.titre,
    required this.prenom,
    required this.nom,
    required this.age,
    required this.newsletter,
    required this.email,
    required this.pays,
    required this.naissance,
    required this.presentation,
  });

  // une copie, dont on change quelques champs (les autres sont conservés) ;
  // "??" : la nouvelle valeur si elle est fournie, sinon l'ancienne
  Profil copyWith({
    String? titre,
    String? prenom,
    String? nom,
    int? age,
    bool? newsletter,
    String? email,
    String? pays,
    String? naissance,
    String? presentation,
  }) {
    return Profil(
      titre: titre ?? this.titre,
      prenom: prenom ?? this.prenom,
      nom: nom ?? this.nom,
      age: age ?? this.age,
      newsletter: newsletter ?? this.newsletter,
      email: email ?? this.email,
      pays: pays ?? this.pays,
      naissance: naissance ?? this.naissance,
      presentation: presentation ?? this.presentation,
    );
  }

  // la valeur d'un champ, désigné par son nom
  Object valeur(Champ c) => switch (c) {
    Champ.titre => titre,
    Champ.prenom => prenom,
    Champ.nom => nom,
    Champ.age => age,
    Champ.newsletter => newsletter,
    Champ.email => email,
    Champ.pays => pays,
    Champ.naissance => naissance,
    Champ.presentation => presentation,
  };

  // une copie dont UN champ, désigné par son nom, a une nouvelle valeur
  Profil avec(Champ c, Object v) => switch (c) {
    Champ.titre => copyWith(titre: v as String),
    Champ.prenom => copyWith(prenom: v as String),
    Champ.nom => copyWith(nom: v as String),
    Champ.age => copyWith(age: v as int),
    Champ.newsletter => copyWith(newsletter: v as bool),
    Champ.email => copyWith(email: v as String),
    Champ.pays => copyWith(pays: v as String),
    Champ.naissance => copyWith(naissance: v as String),
    Champ.presentation => copyWith(presentation: v as String),
  };

  Map<String, Object> versJson() => {for (final c in Champ.values) c.name: valeur(c)};
}

// l'état complet : les valeurs, et les champs déjà quittés
class Etat {
  final Profil valeurs;
  final Set<Champ> touches;

  const Etat(this.valeurs, this.touches);
}

// les actions possibles. "sealed" : il n'y en a pas d'autres que celles de
// ce fichier, le compilateur le sait
sealed class ActionProfil {
  const ActionProfil();
}

class Modifier extends ActionProfil {
  final Champ champ;
  final Object valeur;
  const Modifier(this.champ, this.valeur);
}

class Quitter extends ActionProfil {
  final Champ champ;
  const Quitter(this.champ);
}

class Majuscules extends ActionProfil {
  const Majuscules();
}

class Reinitialiser extends ActionProfil {
  const Reinitialiser();
}

// le réducteur : il ne MODIFIE jamais l'état reçu, il en renvoie un nouveau.
// Le switch "déstructure" chaque action : Modifier(:final champ, ...) lit
// ses champs dans des variables du même nom
Etat reducteur(Etat etat, ActionProfil action) => switch (action) {
  Modifier(:final champ, :final valeur) => Etat(etat.valeurs.avec(champ, valeur), etat.touches),
  Quitter(:final champ) => Etat(etat.valeurs, {...etat.touches, champ}),
  Majuscules() => Etat(
    etat.valeurs.copyWith(prenom: etat.valeurs.prenom.toUpperCase(), nom: etat.valeurs.nom.toUpperCase()),
    etat.touches,
  ),
  Reinitialiser() => const Etat(depart, {}),
};

// lib/ex07_validation/main.dart - valider un formulaire, à la main
// -------------------------------------------------------------------------
// Une fonction PURE, valider(compte), renvoie les erreurs des champs ; on
// l'appelle à chaque build(), les erreurs sont donc toujours à jour.
// On ne les montre pas d'emblée (un formulaire vide couvert de rouge est
// désagréable) : seulement pour un champ déjà quitté ("touché"). L'envoi
// marque tous les champs comme touchés, puis n'agit que si le formulaire
// est valide. Un TextField affiche une erreur sous le champ, en rouge,
// quand on lui donne un texte d'erreur : InputDecoration(errorText: ...).
//
// Mêmes règles que le serveur RdvMedecins (formulaire "Créer un compte").
// ATTENTION : cette validation n'est qu'un CONFORT pour l'utilisateur (une
// réponse immédiate, sans aller-retour avec le serveur). Elle ne protège
// rien : n'importe qui peut envoyer au serveur une requête fabriquée à la
// main (curl...). Le serveur revalide donc TOUJOURS tout (cf. exemple 25).
// =========================================================================

import 'package:flutter/material.dart';

enum Champ { titre, prenom, nom, login, password, confirmation }

// un "record" : un petit groupe de valeurs nommées, sans classe à écrire
typedef Compte = ({String titre, String prenom, String nom, String login, String password, String confirmation});

const titres = ['Mr', 'Mme', 'Melle'];
final formatLogin = RegExp(r'^[a-z0-9._-]{1,30}$');
const motDePasseMin = 6;

// les règles : une fonction pure, qui ne dépend que de son argument.
// Elle renvoie, pour chaque champ en erreur, son message
Map<Champ, String> valider(Compte c) {
  final erreurs = <Champ, String>{};
  if (!titres.contains(c.titre)) erreurs[Champ.titre] = 'Choisissez un titre dans la liste.';
  if (c.prenom.trim().isEmpty) {
    erreurs[Champ.prenom] = 'Le prénom est obligatoire.';
  } else if (c.prenom.length > 20) {
    erreurs[Champ.prenom] = 'Le prénom ne doit pas dépasser 20 caractères.';
  }
  if (c.nom.trim().isEmpty) {
    erreurs[Champ.nom] = 'Le nom est obligatoire.';
  } else if (c.nom.length > 20) {
    erreurs[Champ.nom] = 'Le nom ne doit pas dépasser 20 caractères.';
  }
  if (c.login.isEmpty) {
    erreurs[Champ.login] = 'Le login est obligatoire.';
  } else if (!formatLogin.hasMatch(c.login)) {
    erreurs[Champ.login] = 'Lettres minuscules non accentuées, chiffres, point, tiret, souligné.';
  }
  if (c.password.isEmpty) {
    erreurs[Champ.password] = 'Le mot de passe est obligatoire.';
  } else if (c.password.length < motDePasseMin) {
    erreurs[Champ.password] = 'Au moins $motDePasseMin caractères.';
  }
  // une règle qui compare DEUX champs
  if (c.confirmation != c.password) {
    erreurs[Champ.confirmation] = 'La confirmation ne correspond pas au mot de passe.';
  }
  return erreurs;
}

      return;

              autovalidateMode: AutovalidateMode.onUserInteraction,
              validator: (v) {
                if (v == null || v.isEmpty) return 'Le mot de passe est obligatoire.';
                return v.length < 6 ? 'Au moins 6 caractères.' : null;
              },
              // le mot de passe change : la confirmation est revalidée
              // (si elle a déjà été saisie)
              onChanged: (_) {
                final confirmation = _cleConfirmation.currentState!;
                if (confirmation.value?.isNotEmpty ?? false) confirmation.validate();

              onSaved: (v) => _compte['password'] = v!,

              key: _cleConfirmation,
              obscureText: true,
              decoration: const InputDecoration(labelText: 'Confirmation', errorMaxLines: 2),

            const SizedBox(height: 16),
            FilledButton(onPressed: _creer, child: const Text('Créer le compte')),

          ],

class Creneau {
  final int hdebut;
  final int mdebut;
  final int hfin;
  final int mfin;

  const Creneau(this.hdebut, this.mdebut, this.hfin, this.mfin);
}

enum Partie { tout, debut, fin }

// "8:05" plutôt que "8:5"
String _heure(int h, int m) => '$h:${m.toString().padLeft(2, '0')}';

// un paramètre FACULTATIF, avec sa valeur par défaut : [Partie partie = Partie.tout]
String horaire(Creneau c, [Partie partie = Partie.tout]) => switch (partie) {
  Partie.debut => _heure(c.hdebut, c.mdebut),
  Partie.fin => _heure(c.hfin, c.mfin),
  Partie.tout => '${_heure(c.hdebut, c.mdebut)} - ${_heure(c.hfin, c.mfin)}',
};

// une EXTENSION du type String : de nouvelles méthodes pour TOUTES les chaînes
extension MiseEnForme on String {
  // "marie pelissier" -> "Marie Pelissier" ; \p{L} : une lettre, accentuée ou non
  String get majusculeInitiale => replaceAllMapped(
    RegExp(r'\p{L}+', unicode: true),
    (m) => m[0]![0].toUpperCase() + m[0]!.substring(1).toLowerCase(),
  );

  // "Marie PELISSIER" -> "MP"
  String get initiales =>
      split(RegExp(r'\s+')).where((mot) => mot.isNotEmpty).map((mot) => mot[0].toUpperCase()).join();
}

// "2026-10-05" (le format de l'API RdvMedecins) -> une date
DateTime versDate(String jour) => DateTime.parse(jour);
