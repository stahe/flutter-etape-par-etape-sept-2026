    2.1. Installer les outils

    1. Node.js : télécharger et installer la version 22 (ou plus récente) depuis nodejs.org. Vérifier l’installation dans un terminal :

    1. Visual Studio Code (VSCode) : téléchargeable gratuitement sur code.visualstudio.com. Installer l’extension « TypeScript and JavaScript Language Features » (généralement déjà intégrée).

    2. [MySQL] 8 : installer par exemple via XAMPP, Laragon (sous Windows) ou directement [MySQL] Community Server. Un outil d’administration graphique (phpMyAdmin, [MySQL] Workbench, DBeaver, HeidiSQL…) facilite la suite. Par la suite, l’outil Laragon est utilisé.

    2.3. Android Studio et les outils de ligne de commande Android

    La cible mobile de ce cours est un téléphone [Android]. Pour compiler l'application et l'installer sur ce téléphone, [Flutter] a besoin du SDK [Android], qui s'installe avec [Android Studio], l'environnement de développement de Google. [Android Studio] n'est pas utilisé pour écrire le code - l'éditeur reste [VSCode] - il ne sert ici qu'à installer et à mettre à jour le SDK [Android].

    1. [Android Studio] : le télécharger gratuitement à l'adresse [https://developer.android.com/studio] puis l'installer. Au premier lancement, l'assistant propose une installation standard : l'accepter, il télécharge le SDK [Android].

    1. Ouvrir le [SDK Manager] d'[Android Studio] (menu [Tools / SDK Manager] lorsqu'un projet est ouvert, ou [More Actions / SDK Manager] depuis l'écran d'accueil) : c'est lui qui installe et met à jour les composants du SDK [Android].
    1. Onglet [SDK Platforms] : vérifier qu'une plateforme [Android] récente est installée (la documentation de [Flutter] indique l'API 36 au moment de l'écriture).

    1. Onglet [SDK Tools] : cocher [Android SDK Command-line Tools (latest)], [Android SDK Build-Tools] et [Android SDK Platform-Tools] (ainsi que [Android Emulator] si vous voulez tester sur un émulateur), puis cliquer sur [Apply]. La documentation de [Flutter] recommande aussi [CMake] et [NDK (Side by side)]. Ce sont les [Android SDK Command-line Tools] qui manquent lorsque [flutter doctor] affiche « cmdline-tools component is missing ».
    2. Accepter les licences du SDK [Android] en tapant la commande suivante dans un terminal du projet Flutter, puis en répondant [y] à chaque question, jusqu'au message « All SDK package licenses accepted. » : 
    flutter doctor –android-licenses

    [Remarque] : avec la version 23.0 des [Android SDK Command-line Tools], la commande ci-dessus peut se terminer aussitôt, sans rien demander, en affichant « The --licenses option is no longer needed ». C'est un problème connu de [Flutter] (issues 191558 et 191487 sur github.com/flutter/flutter). Contournement : dans le [SDK Manager], onglet [SDK Tools], cocher [Show Package Details], remplacer la version 23.0 des [Android SDK Command-line Tools] par la version 22.0, cliquer sur [Apply] puis relancer la commande.

    2.4. Préparer un émulateur Android

    À défaut de téléphone, on peut tester l'application sur un émulateur [Android] : un téléphone virtuel qui s'exécute dans une fenêtre de l'ordinateur. [Android Studio] installe le programme [Android Emulator] (s'il a été coché dans le [SDK Manager], cf. ci-dessus) mais pas d'appareil virtuel prêt à l'emploi : il faut en créer un.

    1. [Prérequis] : la virtualisation doit être activée dans le [BIOS] de l'ordinateur et, sous [Windows], la fonctionnalité [Plateforme de l'hyperviseur Windows] doit être cochée ([Panneau de configuration / Programmes / Activer ou désactiver des fonctionnalités Windows]), ce qui demande un redémarrage. Sans cela, l'émulateur ne démarre pas ou reste très lent.
    2. Ouvrir le [Device Manager] d'[Android Studio] : [More Actions / Virtual Device Manager] depuis l'écran d'accueil, ou [Tools / Device Manager] lorsqu'un projet est ouvert (selon la version : [View / Tool Windows / Device Manager]).

    1. Cliquer sur [Create Device], choisir un modèle (par exemple [Pixel 8]) puis [Next]. Choisir une image système [Android] récente pour le processeur [x86_64] et la télécharger avec le lien [Download] situé à côté, puis [Next] et [Finish].

    1. Démarrer l'émulateur avec le bouton [Play] du [Device Manager] :

    1. Attendre que l'écran d'accueil d'[Android] soit affiché dans la fenêtre de l'émulateur : le premier démarrage peut durer plusieurs minutes. Vérifier ensuite que [Flutter] voit l'émulateur, qui doit figurer dans la liste (par exemple [emulator-5554], plateforme [android-x64]) : 
    flutter devices

Essayer dans l'ordre : (1) attendre l'écran d'accueil puis relancer la commande ; (2) redémarrer [adb] avec les trois commandes suivantes (sous [Windows], dans [PowerShell]), la dernière devant afficher « device » et non « offline » ; (3) dans le [Device Manager], menu [⋮] de l'appareil, choisir [Cold Boot Now], voire [Wipe Data] en dernier recours.

    flutter run -d emulator-5554

    2.5. Préparer le téléphone Android

    Pour exécuter l'application sur un vrai téléphone [Android], celui-ci doit accepter d'être piloté depuis l'ordinateur :

    1. Activer les options pour les développeurs : ouvrir [Paramètres / À propos du téléphone] puis appuyer plusieurs fois (7 en général) sur [Numéro de build] jusqu'à ce que le téléphone indique que vous êtes développeur. Les intitulés exacts varient selon le fabricant.
    2. Activer le [Débogage USB] dans les [Options pour les développeurs] (menu ajouté par l'étape précédente).
    3. Brancher le téléphone à l'ordinateur avec un câble USB qui transfère des données (pas seulement de la charge) et accepter, sur le téléphone, la demande d'autorisation du débogage USB. Sous Windows, si le téléphone n'est pas reconnu, installer le pilote USB de son fabricant (« OEM USB drivers », cf. [https://developer.android.com/studio/run/oem-usb]).
    4. Vérifier que [Flutter] voit le téléphone : il doit apparaître dans la liste affichée par la commande suivante, avec la plateforme [android] : 
    flutter devices

    Le téléphone accèdera au serveur [NestJS] par l'adresse IP de l'ordinateur sur le réseau local (et non par [localhost]) : ce réglage est décrit au chapitre 5.
